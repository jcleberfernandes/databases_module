# Três problemas concretos no modelo

## Problema 1 — A mesma mensagem é salva em três lugares

No arquivo [`fastapi/app/main.py`](./fastapi/app/main.py), a mensagem é salva
no PostgreSQL nas linhas 54–58, no MongoDB nas linhas 61–63 e no Redis nas
linhas 66–67.

Isso pode causar um problema: o PostgreSQL pode salvar a mensagem, mas o
MongoDB pode apresentar um erro. Nesse caso, os bancos ficam diferentes: a
mensagem existe em um lugar, mas não existe no outro. O programa não consegue
desfazer automaticamente tudo o que já foi salvo.

**Como melhorar:** usar o PostgreSQL como o banco principal e usar MongoDB e
Redis apenas para guardar cópias ou informações que possam ser refeitas.

## Problema 2 — O Redis guarda somente a última mensagem

Nas linhas 65–67 de [`fastapi/app/main.py`](./fastapi/app/main.py), todas as
mensagens são salvas com o nome `hello:last`.

Isso significa que uma mensagem nova substitui a anterior. Se duas pessoas
enviarem mensagens quase ao mesmo tempo, uma delas pode deixar de aparecer no
Redis. O contador e a última mensagem também são salvos em momentos diferentes,
por isso eles podem não representar exatamente a mesma situação.

**Como melhorar:** guardar cada mensagem com um identificador diferente ou
usar o Redis somente como um lugar temporário para a última mensagem.

## Problema 3 — A mensagem pode ser grande demais

Na linha 21 de [`fastapi/app/main.py`](./fastapi/app/main.py), o programa
verifica apenas se `msg` tem pelo menos um caractere. No banco, a coluna também
é um texto sem limite definido, na linha 29 de
[`fastapi/app/clients.py`](./fastapi/app/clients.py).

Assim, alguém poderia enviar uma mensagem muito grande e ocupar muito espaço
no banco. Também não existe uma regra dizendo se mensagens iguais podem ser
repetidas.

**Como melhorar:** definir um tamanho máximo para a mensagem e decidir se
mensagens iguais serão aceitas ou não.
