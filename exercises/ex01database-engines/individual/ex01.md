# MongoDB ou Redis?

Neste exemplo, o PostgreSQL deve continuar sendo o lugar principal para
guardar as mensagens. Ele guarda cada mensagem em uma linha da tabela
`hello`, como aparece nas linhas 54–58 de
[`fastapi/app/main.py`](./fastapi/app/main.py).

Mesmo assim, algumas partes podem ficar melhores no MongoDB ou no Redis,
dependendo da finalidade.

## MongoDB

O MongoDB pode ser útil quando cada mensagem tiver informações diferentes.
Por exemplo, uma mensagem poderia ter `tags`, autor, localização ou outros
campos. O MongoDB permite guardar essas informações juntas no mesmo documento.

Neste programa, o documento do MongoDB é criado nas linhas 61–63 de
[`fastapi/app/main.py`](./fastapi/app/main.py). Ele guarda a mensagem, uma
lista de tags e a data:

```json
{
  "msg": "Olá",
  "tags": ["a", "b"],
  "created_at": "data e hora"
}
```

Isso é simples para ler, porque todas essas informações estão juntas. Porém,
neste exemplo as tags são sempre `["a", "b"]`. Por isso, não existe uma grande
vantagem em usar o MongoDB somente para esse campo.

**Conclusão sobre o MongoDB:** ele seria uma boa escolha se as mensagens
passassem a ter informações variadas. Para o exemplo atual, o PostgreSQL já é
suficiente para guardar o histórico.

## Redis

O Redis é útil para informações rápidas e temporárias. Neste programa, ele
guarda a última mensagem na chave `hello:last` e o total de mensagens na chave
`hello:count`, nas linhas 65–67 de
[`fastapi/app/main.py`](./fastapi/app/main.py).

Por exemplo, a aplicação pode consultar rapidamente qual foi a última
mensagem. Se o Redis parar, esses dados podem ser criados novamente a partir
do PostgreSQL.

Por outro lado, o Redis não é a melhor escolha para guardar todo o histórico.
Ele usa a memória do computador e, se todas as mensagens fossem guardadas
nele, poderia ocupar muito espaço. Além disso, neste código uma nova mensagem
substitui o valor anterior de `hello:last`.

**Conclusão sobre o Redis:** ele é uma boa escolha para a última mensagem, um
contador ou um cache temporário. Não deve ser o único lugar onde o histórico
fica guardado.

## Decisão final

Para este projeto:

- **PostgreSQL:** guardar todas as mensagens, pois é o histórico principal.
- **MongoDB:** usar somente se as mensagens tiverem informações variadas ou
  diferentes umas das outras.
- **Redis:** usar para a última mensagem e para o contador, pois essas
  informações precisam ser acessadas rapidamente e podem ser refeitas.
